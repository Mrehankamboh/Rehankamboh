Case study

Fundora — trade with institutional discipline

Prop-trading marketing site and trader portal. Static HTML/CSS/JS with a Node API and Neon Postgres for auth, challenges, rewards, pricing, and support.

RoleFull-stack
StackHTML, CSS, JS, Node, Neon
FocusLanding + portal + API
Relatedfundora-admin (Next.js)

Overview

Fundora is a classical prop evaluation brand: clear rules, measured risk, and capital when traders earn it. The public site sells 1-Step and 2-Step challenges (capital up to $200K, 80% reward split, MT5 & cTrader).

Behind the marketing layer sits a full trader portal and JSON API — register/login (email + Google OAuth), challenge purchase, live prices from Neon, rewards requests, and a floating support chat that writes tickets to the same database as the admin app.

What’s included

  1. [001]

    Marketing landing

    Hero with interactive globe, challenge planner (prices from /api/prices), platforms, FAQ, CTA, and load curtain. Auth pages: login, register, forgot password.

  2. [002]

    Trader portal

    Session-guarded shell with dashboard, challenges, rewards, platforms, rules, billing, certificates, support, account, and settings. Challenge checkout activates plans after payment.

  3. [003]

    Backend API

    Node server.cjs serves static files and JSON routes: auth, profile, challenges, rewards, tickets, health. Schema migrates on first use — users, sessions, challenge_prices, tickets, and more.

  4. [004]

    Admin companion

    Separate Next.js app (fundora-admin) shares the same Neon database — operators manage support calls and admin users against the live Fundora data.

Product highlights

  1. [001]

    1-Step & 2-Step challenges

    Faster single evaluation or classic two-phase path. Account sizes and fees load live from Neon.

  2. [002]

    Auth that ships

    Email/password with bcrypt sessions, Gmail SMTP for welcome/reset mail, and Google OAuth for one-tap login.

  3. [003]

    Support widget

    Floating chat on the marketing site writes tickets and messages to Neon — visible in the admin Call inbox.

  4. [004]

    Brand system

    Dark institutional look — Cormorant + DM Sans, Fundora mark, trading photography, and motion that stays calm rather than loud.

Stack

HTML, CSS, and vanilla JS on the front. Node server for static + API. Neon Postgres via @neondatabase/serverless. Sessions with bcryptjs. Mail via nodemailer. Admin UI in Next.js (separate repo, same database).
